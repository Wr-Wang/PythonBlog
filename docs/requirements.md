# PythonBlog 需求说明

**文档版本：** 2.3  

**适用范围：** 本仓库 **PythonBlog** 全栈应用；**基线需求（§3）** 与当前后端 [`backend/app`](../backend/app)、前端 [`frontend/src`](../frontend/src) 行为一致，代码或规则变更时须同步修订本文档与测试。**扩展需求（§4）** 为规划项，经评审排期后方可纳入基线。**§4.12～§4.16** 为对标主流博客的能力扩展；**§4.17（HUX）** 为 **人性化交互、易用性与年轻化审美/版式** 的专项要求（与 UXR/AXP 协同），优先级以评审为准。

**技术栈（现状）：** 后端 FastAPI + SQLAlchemy + SQL Server（pyodbc）；前端 Vue 3 + Vue Router + Axios；认证 JWT（Bearer）。

## 1. 目标与范围

### 1.1 项目目标

- 提供 **面向访客的公开博客阅读与评论** 能力。
- 提供 **面向已登录管理员的后台**，用于管理文章、分类、标签、用户与评论，以及上传图片；**更丰富的正文媒体（多图、视频、复杂排版）** 见 §4 IMG / VID / CNT 规划项。
- 后端同时可提供 **OpenAPI 文档**（`/docs`）与 **健康检查**（`/api/health`），支持本地开发与 IIS 等部署方式（详见同目录其他部署文档）。
- **演进目标（扩展）：** 在可维护前提下对齐 **现代博客常见能力**——如阅读时长与主题、定时发布与草稿体验、相关推荐与系列连载、Newsletter/订阅、隐私友好统计、结构化 SEO、无障碍与可选 PWA（详见 §4.12～§4.16）。
- **体验与审美（扩展）：** 在 **可访问、不浮夸** 的前提下，提升 **人性化文案、易用流程、信息层级与版式美感**，贴合当前年轻用户常见的 **简洁、留白、清晰字体与适度动效** 等审美取向（详见 **§4.17 HUX**）。

### 1.2 范围说明（基线 vs 扩展）

- **基线（§3）** 已覆盖的能力见各需求 ID；下列能力在 **当前代码中未实现或仅为占位**，详细规格见 **§4 扩展需求** 与 **§5 路线图**。
- **角色/权限细分**、**访客注册**、**第三方登录**、**邮件通知**、**全文搜索**、**RSS/sitemap**、**评论审核工作流** 等：基线未交付；以扩展需求表为准跟踪。
- **正文内图片图集、本地上传视频、第三方视频嵌入、目录/公式/图表级复杂文章**：基线仅支持文本型 `content` + 封面 URL + 单图上传接口；细化能力见 **§4.8～§4.10**。
- **热门博客常见体验**（深浅色、阅读进度、定时发布、相关文章、Newsletter、JSON-LD、Cookie 同意、PWA 等）：基线未交付；见 **§4.12～§4.16**。
- **人性化交互、空状态与加载态、设计令牌、移动端易用、年轻化视觉与版式**：基线未强制；见 **§4.17 HUX**（与 **UXR** 深浅色、**AXP** 对比度协同）。

## 2. 角色与术语

| 角色 | 说明 |
|------|------|
| **访客** | 未登录用户，可浏览已发布文章列表与详情、在已发布文章下发表评论（含回复）。 |
| **管理员（基线）** | 已登录的后台用户（`User.is_active = true`），可访问所有依赖 JWT 的管理接口；**系统不区分职级**。扩展规划中的细分角色见 §4 RBAC。 |

**术语：** `slug` 为 URL 友好唯一标识（文章、分类、标签均有）；`published` 表示文章是否对访客可见。**复杂文章** 指除纯段落外，含目录、代码高亮、嵌入视频、图集、分节折叠等增强排版（见 §4.10）。**HUX（Humanized UX）** 指面向真实使用场景的文案、反馈与界面层次，**不**将「年轻化」等同于降低可读性或堆砌动效（见 §4.17）。

## 3. 已实现需求（基线 v1）

以下需求与当前实现对齐，可作为 **回归测试** 依据（详见 §8.1）。

### 3.1 系统启动与运行

| ID | 需求描述 |
|----|-----------|
| SYS-01 | 应用启动时应连接配置中的 SQL Server（`DATABASE_URL` 须为 `mssql+pyodbc://` 形式），执行建表、轻量迁移补列及种子数据逻辑。 |
| SYS-02 | 若数据库初始化失败，应仍允许访问 `GET /api/health` 以返回降级状态与错误信息；**除该路径外**，对 `/api/*` 的请求应返回 **503**，提示数据库未就绪。 |
| SYS-03 | 首次初始化时，若配置中的管理员用户名不存在，应自动创建该用户（密码来自配置，经哈希入库）。 |
| SYS-04 | 种子数据应 **幂等** 补齐默认分类、标签及示例文章（按 `slug` 去重，不重复插入同 slug 文章）。 |
| SYS-05 | 上传目录（`upload_dir`）应在运行时可用；上传文件通过 HTTP 静态路径对外访问（与 `main.py` 挂载一致）。 |

### 3.2 认证与会话

| ID | 需求描述 |
|----|-----------|
| AUTH-01 | 用户可通过 `POST /api/auth/login` 提交用户名、密码；校验失败返回统一错误提示（避免用户名枚举策略由实现决定，当前为「用户名或密码错误」）。 |
| AUTH-02 | 禁用用户（`is_active = false`）不可登录，应返回 **403**。 |
| AUTH-03 | 登录成功返回 JWT（`access_token`），载荷包含 `sub`（用户名）与过期时间 `exp`；算法与密钥来自服务端配置。 |
| AUTH-04 | 受保护接口从 `Authorization: Bearer <token>` 解析 JWT，验签通过后按 `sub` 加载用户；无效、过期、用户不存在或已禁用应返回 **401**。 |
| AUTH-05 | `GET /api/auth/me` 返回当前登录用户公开字段；`POST /api/auth/logout` 可为占位，**实际登出由客户端清除令牌**。 |

### 3.3 访客端（公开 API + 前端页面）

| ID | 需求描述 |
|----|-----------|
| PUB-01 | 访客可获取已发布文章列表，支持分页参数（`skip`/`limit`），默认仅 `published_only=true` 的已发布文章。 |
| PUB-02 | 访客可通过 `slug` 获取单篇已发布文章详情；未发布或不存在应 **404**。 |
| PUB-03 | 首页（`/`）展示已发布文章列表（标题、摘要、创建时间等列表项字段以后端 schema 为准）。 |
| PUB-04 | 文章详情页（`/post/:slug`）展示正文及评论区域；评论可嵌套（`parent_id` 回复）。 |
| PUB-05 | 访客可对 **已发布** 文章拉取评论列表；对未发布文章应 **404**。 |
| PUB-06 | 访客可提交评论（昵称、内容等字段以后端 `CommentCreatePublic` 为准）；若指定 `parent_id`，须属于同一篇文章且存在。 |

### 3.4 后台 — 文章

| ID | 需求描述 |
|----|-----------|
| ADM-P-01 | 已登录用户可分页获取 **全部** 文章（含未发布），含管理视图所需字段（如分类、标签、封面等，以后端 `PostAdminOut` 为准）。 |
| ADM-P-02 | 已登录用户可按 ID 获取文章管理详情。 |
| ADM-P-03 | 创建文章时 `slug` 全局唯一；须指定已存在的 `category_id`；可绑定多个标签；记录作者为当前用户。 |
| ADM-P-04 | 更新文章时可改标题、slug、摘要、正文、发布状态、分类、标签、封面 URL 等；`slug` 仍须全局唯一。 |
| ADM-P-05 | 已登录用户可删除文章。 |

**说明（基线）：** 文章正文 `content` 为 **文本字段**（当前实现中通常按 Markdown 渲染）；`cover_image_url` 存封面地址。正文内 **多图图集、本地上传视频、第三方 iframe 视频、自动生成目录、公式/图表** 等不在基线强制范围内，以 **§4 IMG / VID / CNT** 规划为准。

### 3.5 后台 — 分类与标签

| ID | 需求描述 |
|----|-----------|
| ADM-C-01 | 分类、标签均需登录后 CRUD；`slug` 在各自表内唯一。 |
| ADM-C-02 | 删除分类时若仍有文章引用，可能受数据库外键约束；运维/使用上需先调整文章分类（行为与 DB 约束一致）。 |
| ADM-T-01 | 删除标签时，与文章的多对多关联应按数据库设计清理（实现中可依赖级联或等价逻辑）。 |

### 3.6 后台 — 用户

| ID | 需求描述 |
|----|-----------|
| ADM-U-01 | 已登录用户可列表、查看、创建、更新、删除后台用户。 |
| ADM-U-02 | 创建用户时必须设置用户名与密码（密码哈希存储）；可设置是否启用。 |
| ADM-U-03 | 更新用户时可改用户名、密码（可选）、启用状态；用户名唯一。 |
| ADM-U-04 | **禁止删除当前登录用户**，避免锁死后台。 |

### 3.7 后台 — 评论

| ID | 需求描述 |
|----|-----------|
| ADM-M-01 | 已登录用户可分页查看全站评论（含所属文章标题等管理字段）。 |
| ADM-M-02 | 可对单条评论增删改查（含后台代发评论，用于补录或管理）。 |
| ADM-M-03 | 评论与 `post_id`、可选 `parent_id` 的合法性校验与公开接口一致。 |

### 3.8 文件上传

| ID | 需求描述 |
|----|-----------|
| UPL-01 | 已登录用户可通过 `POST /api/upload/image` 上传 **单文件** 图片。 |
| UPL-02 | 仅允许 MIME 为 `image/jpeg`、`image/png`、`image/gif`、`image/webp`；大小不超过 **5MB**。 |
| UPL-03 | 服务端生成唯一文件名并写入配置的上传目录，响应返回可访问的 URL 路径（如 `/uploads/<filename>`）。 |
| UPL-04 | 开发环境下，前端开发服务器应将 `/uploads` 代理至后端以便预览图片（与 Vite 配置一致）。 |

### 3.9 前端路由与体验

| ID | 需求描述 |
|----|-----------|
| FE-01 | 访问 `/admin` 下需登录的子路由时，若本地无令牌，应跳转至 `/admin/login`，并支持登录后跳回原目标（`redirect` 查询参数）。 |
| FE-02 | 管理端各子模块：文章、分类、标签、用户、评论等，与后端 API 对应（具体页面以 `frontend/src` 为准）。 |
| FE-03 | Axios 请求应自动附带 `localStorage` 中的 JWT（键名与实现一致，如 `blog_token`）。 |

### 3.10 生产构建与托管

| ID | 需求描述 |
|----|-----------|
| DEP-01 | 若存在前端构建产物目录 `frontend/dist`，后端可将 SPA 挂载为同域站点，支持前端路由回退到 `index.html`（与 `frontend_spa` 实现一致）。 |
| DEP-02 | 未构建前端时，根路径可返回 JSON 提示构建方式，并给出 Swagger/ReDoc/健康检查链接。 |

## 4. 扩展需求（规划 v2+）

以下条目为 **规划**，尚未作为基线验收；优先级：**Must** = 下一版本强烈建议；**Should** = 重要增强；**Could** = 择机。**依赖** 标注前置条件。**验收要点** 供未来用例设计引用。

### 4.1 角色与权限（RBAC）

| ID | 优先级 | 需求描述 | 依赖 | 验收要点 |
|----|--------|----------|------|----------|
| RBAC-01 | Should | 定义至少一种非全局能力划分（如 `admin` / `editor` / `viewer`，或「作者仅可编辑本人文章」）。 | 用户模型或关联表扩展 | 无权限访问受保护 API 返回 **403**；OpenAPI 或文档列出各角色能力。 |
| RBAC-02 | Should | 权限判定在服务端统一实现（依赖注入或装饰器），禁止仅依赖前端隐藏菜单。 | RBAC-01 | 直接请求 API 时越权行为与角色矩阵一致。 |
| RBAC-03 | Could | JWT 载荷或服务端会话中携带角色/权限声明，并与数据库可吊销状态一致。 | RBAC-01 | 禁用用户或吊销角色后立即失效（在可接受的延迟内）。 |

### 4.2 评论治理（MOD）

| ID | 优先级 | 需求描述 | 依赖 | 验收要点 |
|----|--------|----------|------|----------|
| MOD-01 | Should | 评论增加状态（如 `pending` / `approved` / `rejected`）；**访客可见列表仅展示已通过**。 | `Comment` 模型与迁移 | 待审核评论不出现在公开接口；后台可筛选。 |
| MOD-02 | Could | 后台批量通过/拒绝/删除；可选垃圾过滤（频率限制、关键词、验证码见 SEC）。 | MOD-01 | 批量操作结果可审计（至少记录数量与失败原因）。 |
| MOD-03 | Could | 新评论默认「待审核」或可配置为「先发后审」（站点级开关）。 | MOD-01 | 配置变更后行为符合说明文档。 |

### 4.3 发现与 SEO（DISC）

| ID | 优先级 | 需求描述 | 依赖 | 验收要点 |
|----|--------|----------|------|----------|
| DISC-01 | Could | 提供 RSS 或 Atom 订阅端点，条目与已发布文章一致。 | 公开文章查询 | Feed 校验通过常见阅读器；更新频率可接受。 |
| DISC-02 | Could | 提供 `sitemap.xml`（或索引），包含公开文章与主要栏目 URL。 | 路由与 slug 稳定 | 搜索引擎抓取工具可解析。 |
| DISC-03 | Could | 文章或站点级 SEO 元数据（`title`/`description`/OG 标签）在 SPA 或 SSR 策略下可配置。 | 前端渲染策略 | 分享预览符合配置。 |
| DISC-04 | Should | 输出 **结构化数据**（JSON-LD：`BlogPosting`/`WebSite`/`BreadcrumbList` 等），字段与文章/站点信息一致，可被 Google Rich Results 测试校验。 | 公开文章与站点配置 | 无无效 JSON；与可见正文不矛盾。 |
| DISC-05 | Should | 每篇公开文章具备 **规范链接**（`link rel="canonical"`）与一致 OG `url`，避免重复内容问题。 | 路由与域名配置 | 换域名或 HTTP/HTTPS 策略时仍唯一。 |

### 4.4 站内搜索（SRCH）

| ID | 优先级 | 需求描述 | 依赖 | 验收要点 |
|----|--------|----------|------|----------|
| SRCH-01 | Should | 支持按关键词搜索**已发布**文章，范围至少包含标题与摘要；结果分页。 | 索引或 LIKE 策略 | 响应时间与结果相关性在可接受范围；无权限泄漏未发布内容。 |
| SRCH-02 | Could | 扩展至正文全文；SQL Server 全文索引或外部搜索引擎（需部署约定）。 | SRCH-01 | 大数据量下仍有明确 SLO 或降级策略。 |

### 4.5 安全加固（SEC）

| ID | 优先级 | 需求描述 | 依赖 | 验收要点 |
|----|--------|----------|------|----------|
| SEC-01 | Must | 对登录、评论提交、上传等接口实施 **速率限制**（按 IP 或组合键），超限返回 **429** 及明确提示。 | 中间件或网关 | 压测下触发阈值行为稳定。 |
| SEC-02 | Should | 生产环境强制强 `SECRET_KEY`、文档化密钥轮换流程；推荐安全响应头（如 `X-Content-Type-Options` 等）由网关或应用配置。 | 部署 | 安全扫描或检查清单通过基线项。 |
| SEC-03 | Could | 若引入 Cookie 会话，须 `Secure`/`HttpOnly`/`SameSite` 策略说明。 | 认证改造 | 与渗透测试要求一致。 |

### 4.6 可观测性与运维（OPS）

| ID | 优先级 | 需求描述 | 依赖 | 验收要点 |
|----|--------|----------|------|----------|
| OPS-01 | Should | `/api/health` 扩展：如数据库连通耗时、应用版本或迁移版本号（可选字段）。 | 无 | 运维可据此做探活与发布验证。 |
| OPS-02 | Could | 结构化日志 + 请求 ID（`X-Request-ID`），便于与 IIS/反向代理日志关联。 | 日志收集 | 单条请求可端到端追踪。 |

### 4.7 媒体与存储（MED）

| ID | 优先级 | 需求描述 | 依赖 | 验收要点 |
|----|--------|----------|------|----------|
| MED-01 | Could | 上传图片生成 WebP 或多尺寸缩略图；存储仍可在本地或迁移至对象存储。 | UPL 扩展 | 页面引用 URL 稳定；回源失败有降级。 |
| MED-02 | Could | 对象存储（S3 兼容/OSS）时，文章内仅保存公开 URL；上传凭证不暴露给浏览器直传需安全设计。 | 配置与 CORS | 符合最小权限原则。 |
| MED-03 | Could | 可选 **媒体库元数据**（原文件名、MIME、宽高、时长、引用计数），支持孤儿文件清理与配额；与 IMG/VID 上传入口共用。 | 模型与任务 | 删除文章或改稿后资源可追踪。 |

### 4.8 图片与正文内媒体（IMG）

| ID | 优先级 | 需求描述 | 依赖 | 验收要点 |
|----|--------|----------|------|----------|
| IMG-01 | Should | **正文内插图**：后台编辑时支持插入图片（上传至本站 `/uploads` 或粘贴 URL）；与 **封面** `cover_image_url` 职责分离、互不覆盖。 | UPL 或扩展 | 保存后再打开编辑，图片地址可逆、可替换。 |
| IMG-02 | Should | 支持每张图 **alt 文案**（无障碍与 SEO）；可选 title/说明。 | 编辑器与 schema | 前台渲染带 `alt`；缺失时给出后台警告或默认值策略。 |
| IMG-03 | Could | **图集/相册**：块级结构（如 `::: gallery` 或 JSON 块）包含多图顺序与可选说明。 | CNT-01 | 访客端展示为网格/轮播，移动端可滑动。 |
| IMG-04 | Could | 与 **MED-01** 联动：正文图片 `srcset`/响应式；外链图片可选代理或转存（防盗链与可用性策略在文档中约定）。 | MED-01 | 大列表页与详情页首屏性能达标（见 §6.2）。 |

### 4.9 视频（VID）

| ID | 优先级 | 需求描述 | 依赖 | 验收要点 |
|----|--------|----------|------|----------|
| VID-01 | Should | **嵌入第三方视频**：正文允许 iframe 或 oEmbed，**仅允许配置白名单域名**（如 `youtube.com`、`player.bilibili.com`、Vimeo 等），禁止任意 `src` 以防 XSS。 | CSP 或服务端过滤 | 非白名单 URL 保存失败或渲染时剥离并提示。 |
| VID-02 | Could | **本地上传短视频**（如 `mp4`/`webm`）：独立上传接口或复用媒体接口；限制单文件大小、时长、总空间；存放于 `upload_dir` 或对象存储（MED-02）。 | SEC 限流、存储 | 超限 **400**；可选 FFmpeg 转码为多码率（延后）。 |
| VID-03 | Could | 视频 **poster** 封面图；可选 **字幕**（WebVTT）与多语言轨道。 | VID-02 | 无封面时显示占位；字幕可开关。 |
| VID-04 | Could | 直播流（HLS）或仅外链：若不做，应在文档中明确 **不支持**。 | — | 避免用户误期望。 |

### 4.17 人性化、易用与年轻化视觉（HUX）

面向 **真实使用场景** 的交互与文案，以及在 **可读、可访问** 前提下的 **现代审美与版式**（参考当下独立博客、产品型官网常见取向：清晰层级、适度圆角与留白、克制动效、深浅色一致）。**不绑定** 单一视觉风格，允许通过 **设计令牌** 换肤；具体色值与组件库选型由实现阶段在 UI 规范中确定。

| ID | 优先级 | 需求描述 | 依赖 | 验收要点 |
|----|--------|----------|------|----------|
| HUX-01 | Should | **设计令牌（Design Tokens）**：间距、圆角、阴影层级、语义色（背景/表面/主色/危险/成功等）集中定义，前台与后台 **共用同一套变量**，避免「页面各自一套颜色」。 | CSS 变量或主题文件 | 改主色一处即可全局联动；深浅色（UXR-02）下对比度仍达标（AXP-01）。 |
| HUX-02 | Should | **排版与版式**：正文字体字号、行高、**最大行宽（measure）** 与标题层级（h1～h3）在文章页与列表卡上 **清晰可辨**；长文避免通栏难读；支持系统字体栈与可选 Web 字体（加载失败可降级）。 | 无 | 典型手机与桌面宽度下无横向滚动（除代码/表格）；首屏信息层级一眼可扫。 |
| HUX-03 | Should | **移动端优先**：触控目标 **≥ 约 44×44px**（或等价可点区域）；底部导航/固定按钮避让安全区；表格与代码块在窄屏可横向滚动且提示清晰。 | 响应式布局 | 单手操作场景下主要操作可达。 |
| HUX-04 | Should | **空状态（Empty state）**：无文章、无评论、无搜索结果等场景 **禁止仅空白**；需简短人性化说明 + 可选图标/插画 + 下一步引导（如「去后台写第一篇」仅对管理员可见）。 | 路由与角色 | 用户能理解「为什么空」与「能做什么」。 |
| HUX-05 | Should | **加载与等待**：列表/详情/提交过程使用 **骨架屏、占位或明确进度**，避免布局剧烈跳动（CLS）；后台表格操作可局部 loading。 | 前端状态 | 慢速网络下仍感知「系统在工作」。 |
| HUX-06 | Should | **错误与反馈**：接口失败用 **自然语言** 说明原因与建议（重试、检查登录、联系管理员）；**禁止**向普通访客暴露堆栈或内部路径；成功操作可有轻量提示（toast）或明确跳转。 | Axios 与错误码约定 | 与 PRV-01 统计脚本失败时也不打断阅读。 |
| HUX-07 | Should | **文案与语气**：全站用语一致、口语化但专业；**危险操作**（删除、清空）二次确认，按钮文案用动词（如「删除文章」而非「确定」）。 | 文案规范 | 无冷冰冰仅错误码；后台表单有 placeholder 与简短帮助。 |
| HUX-08 | Could | **动效与质感**：页面切换、列表出现、按钮反馈使用 **短促、可预期** 的过渡；**必须**尊重 `prefers-reduced-motion`，必要时关闭动画。 | CSS/动画 | 动效不拖慢操作、不干扰阅读。 |
| HUX-09 | Could | **年轻化视觉取向（可选预设）**：在 HUX-01 令牌之上提供 **1～2 套外观预设**（如「极简浅灰」「深色高对比」「柔和渐变强调」等），由配置或站点设置切换；**禁止**牺牲对比度与可读性换「炫」。 | 配置 | 切换预设后焦点与链接仍清晰可见。 |
| HUX-10 | Should | **首页与列表**：卡片或列表项 **封面/标题/摘要/元信息** 对齐一致；支持 **视觉呼吸感**（间距统一），避免信息挤作一团；标签与分类用可点击样式区分。 | GRO/UXR | 与相关文章区块（GRO-01）视觉风格统一。 |
| HUX-11 | Could | **后台易用**：后台编辑区与前台 **预览** 或分屏预览（长期可接 EDW）；表单字段分组、折叠高级项；长列表支持搜索与筛选（与 SRCH 协同）。 | 管理端 | 新管理员能在无文档情况下完成发文流程。 |
| HUX-12 | Should | **美与无障碍一致**：「好看」不以 **小号字、低对比、纯图标无标签** 为代价；链接、按钮、焦点环在深浅色下均可见（与 AXP-01、UXR-02 联合验收）。 | 无 | Lighthouse/人工抽查关键页。 |

以下配置通过 `backend/.env` 或环境变量提供，缺省值以 [`app/config.py`](../backend/app/config.py) 为准：

| 变量 | 含义 |
|------|------|
| `DATABASE_URL` | SQL Server 连接串（必填，`mssql+pyodbc://`）。 |
| `ADMIN_USERNAME` / `ADMIN_PASSWORD` | 种子管理员账号（若库中不存在则创建）。 |
| `SECRET_KEY` / `ALGORITHM` / `ACCESS_TOKEN_EXPIRE_MINUTES` | JWT 签名与有效期。 |
| `CORS_ORIGINS` | 逗号分隔的允许来源。 |
| `UPLOAD_DIR` | 上传文件存储目录。 |

**规划项可能新增：** 速率限制阈值、邮件 SMTP、对象存储桶与凭证、功能开关（如开放注册）、**视频单文件大小/时长上限**、**嵌入视频域名白名单**、**Markdown 扩展开关**、**站点公开 URL（用于 canonical/OG）**、**默认时区**、**Newsletter 发件人**、**分析脚本 ID（若启用）**、**功能开关（PWA、i18n、Cookie 横幅）**、**站点外观预设（HUX-09）**、**设计令牌/主题色覆盖** 等；纳入基线时补充上表与 `config.py`。

## 8. 验收建议

### 8.1 基线回归（当前必须满足）

- 无 token 调用任一 `/api/*/admin` 或带 `get_current_user` 的接口 → **401**。
- 数据库停止或错误连接串启动 → `/api/health` 可访问且 `status`/`database` 反映异常；其他 `/api` → **503**。
- 访客仅能看到 `published=true` 的文章；未发布文章的 slug 访问 → **404**。
- 删除当前登录用户 → **400** 且提示不能删除自己。
- 上传超限或非图片类型 → **400**。

### 8.2 扩展功能验收（规划项，待纳入基线后细化）

| 阶段 | 建议验收主题（对应 §5） |
|------|-------------------------|
| 阶段一 | 登录/评论/上传限流与 429；生产密钥与安全头检查；**嵌入视频仅白名单域名** |
| 阶段二 | 角色矩阵与 403；评论审核流与公开列表过滤；基础搜索无泄漏；**Markdown 扩展一致、TOC/代码高亮与正文插图 alt**；**JSON-LD 与 canonical 有效** |
| 阶段三 | Feed/sitemap 可用；**图集/响应式图/WebP 与媒体库**；**本地上传视频限制与 poster**；邮件相关流程（若启用） |
| 阶段四 | **阅读时间/深浅色**；**定时发布**；**相关文章**；**Cookie 同意（若接统计）**；**无障碍抽查**；**设计令牌与版式、空状态/加载/错误文案、移动端触控与易用**（HUX）；可选 **Newsletter/PWA/i18n**、**外观预设** |
