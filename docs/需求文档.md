# PythonBlog 产品需求文档（PRD V1）

**文档版本：** 1.1  
**更新日期：** 2026-04-09  
**文档定位：** 本文档作为 PythonBlog 第一版正式产品需求，覆盖范围、功能、数据、非功能、验收与里程碑。

---

## 1. 产品背景

PythonBlog 是一个内容发布与运营平台，面向两类核心用户：
- 读者：浏览、互动、分享、搜索、订阅内容。
- 管理员/运营人员：管理内容、权限、流程与运营数据。

V1 目标是形成一个可上线、可运营、可持续扩展的博客产品基础盘。

---

## 2. 产品目标与范围

### 2.1 产品目标
- 提供完整的文章生命周期管理（创作、审核、发布、下线、复盘）。
- 提供读者侧互动和基础增长能力（点赞、收藏、分享、推荐、订阅）。
- 提供可控的后台权限体系与可观测运营能力（RBAC、审计、看板、导出）。
- 在一致性、幂等、风控与灰度方面具备生产可用基础。

### 2.2 范围边界（V1）
- **包含：** 前台阅读与互动、后台内容管理、权限管理、运营看板、搜索运营、基础风控与灰度开关。
- **不包含：** 复杂商业化能力（付费订阅、广告竞价）、强社交关系链、跨站多租户。

---

## 3. 角色定义

| 角色 | 说明 |
|---|---|
| 访客 | 未登录用户，可浏览公开内容并按策略互动 |
| 登录用户 | 可执行收藏、点赞、订阅等需要身份的行为 |
| 编辑 | 管理文章内容与基础运营字段 |
| 审核员 | 负责文章/评论审核与流转 |
| 运营 | 负责推荐位、看板分析、搜索运营、灰度策略 |
| 超级管理员 | 负责用户/角色/菜单/权限与系统级配置 |

---

## 4. 核心业务流程

### 4.1 文章流程
草稿 -> 待审 -> 已发布 -> 已下线 / 驳回

### 4.2 互动数据流程
用户行为事件（浏览/点赞/收藏/分享） -> 增量聚合 -> 看板趋势/推荐排序

### 4.3 权限流程
用户绑定角色 -> 角色绑定权限点/菜单 -> 前端展示控制 + 后端接口鉴权

## 5. 功能需求（按模块）

### 5.1 前台内容与互动（FNT）

#### FNT-INT-01 收藏
- 支持收藏/取消收藏，接口幂等。
- 列表与详情可展示收藏数。

#### FNT-INT-02 点赞
- 支持点赞/取消点赞，接口幂等。
- 具备前端防连点与后端防重。

#### FNT-INT-03 分享
- 支持渠道化分享行为记录（channel）。
- 支持复制链接等通用分享能力。

#### FNT-INT-04 举报
- 支持举报原因 + 备注。
- 举报进入后台处理队列。

#### FNT-MET-01 阅读指标
- 提供浏览量、阅读完成率、平均停留时长。
- 指标口径与去重策略由风控模块统一。

#### FNT-SORT-01 排序与推荐
- 支持按时间、热度、权重、编辑推荐排序。
- 支持规则推荐（置顶/权重/热度/时效）。

#### FNT-SRH-01 搜索
- 支持全文搜索、联想、热搜、多条件筛选。

#### FNT-UX-01 阅读体验
- 目录锚点、夜间模式、字号、阅读进度、预计阅读时长。

#### FNT-GRW-01 增长能力
- 订阅、分享海报、OG 卡片能力。

### 5.2 内容数据模型（DAT）

#### DAT-POST-01 文章核心字段
- `favorite_count`、`like_count`、`view_count`、`share_count`
- `rank_level`、`weight`、`hot_score`
- `is_featured`、`is_pinned`
- `published_at`、`offline_at`
- `content_type`、`source_url`
- `review_status`（draft/pending/approved/rejected/offline）

#### DAT-REL-01 行为关系表
- 收藏、点赞、分享、浏览事件、系列关系表。
- 支持去重键与事件明细并存。

#### DAT-CONS-01 一致性策略
- 明细事件 + 聚合计数双轨。
- 在线增量 + 离线对账修正。

### 5.3 权限与后台管理（ADM）

#### ADM-AUTH-01 RBAC 模型
- 角色管理、菜单管理、权限点管理。
- 支持按钮级权限与 API 权限映射。
- 支持数据范围权限（all/self/...）。

#### ADM-AUTH-02 权限点命名规范（按钮级）
- 权限点按 `模块.资源.动作` 命名，例如：
  - `admin.users.create`
  - `admin.users.update`
  - `admin.users.delete`
  - `admin.roles.bind_permissions`
  - `admin.roles.bind_menus`
- 页面级权限仅用于“是否可进入页面”；业务能力以按钮/动作权限为准。

#### ADM-AUTH-03 按钮级权限清单（V1）

**用户管理页（`/admin/users`）**
- `新增用户`按钮 -> `admin.users.create`
- `编辑用户`按钮 -> `admin.users.update`
- `删除用户`按钮 -> `admin.users.delete`
- `绑定角色`按钮 -> `admin.users.bind_roles`
- `保存角色绑定`按钮 -> `admin.users.bind_roles.save`

**权限管理-角色Tab（`/admin/permissions`）**
- `新增角色`按钮 -> `admin.roles.create`
- `编辑角色`按钮 -> `admin.roles.update`
- `绑定权限点`按钮 -> `admin.roles.bind_permissions`
- `保存权限点绑定`按钮 -> `admin.roles.bind_permissions.save`
- `菜单绑定`按钮 -> `admin.roles.bind_menus`
- `保存菜单绑定`按钮 -> `admin.roles.bind_menus.save`

**权限管理-菜单Tab（`/admin/permissions`）**
- `新增菜单`按钮 -> `admin.menus.create`
- `编辑菜单`按钮 -> `admin.menus.update`
- `隐藏/显示菜单`按钮 -> `admin.menus.visibility.update`

**文章管理页（`/admin/posts`）**
- `新增文章`按钮 -> `admin.posts.create`
- `编辑文章`按钮 -> `admin.posts.update`
- `删除文章`按钮 -> `admin.posts.delete`
- `置顶/取消置顶`按钮 -> `admin.posts.pin.update`
- `精选/取消精选`按钮 -> `admin.posts.feature.update`
- `立即发布`按钮 -> `admin.posts.publish.now`
- `立即下线`按钮 -> `admin.posts.offline.now`
- `保存定时发布/下线`按钮 -> `admin.posts.schedule.update`

**运营看板页（`/admin/dashboard`）**
- `查看看板`按钮/入口 -> `admin.dashboard.view`
- `导出CSV`按钮 -> `admin.dashboard.export.csv`
- `导出XLSX`按钮 -> `admin.dashboard.export.xlsx`

#### ADM-AUTH-04 前后端权限一致性规则
- 前端：无权限按钮默认不展示；如需展示则置灰并给出无权限提示。
- 后端：所有写操作接口必须做权限点校验，禁止仅靠前端隐藏。
- 任一按钮对应的接口需在权限点映射表中有唯一归属，不允许一键多义。

#### ADM-AUTH-05 按钮权限点 -> 后端 API 映射表（V1）

| 页面 | 按钮/动作 | 权限点 | 后端 API（建议映射） |
|---|---|---|---|
| 用户管理 | 新增用户 | `admin.users.create` | `POST /api/users/admin` |
| 用户管理 | 编辑用户 | `admin.users.update` | `PATCH /api/users/admin/{user_id}` |
| 用户管理 | 删除用户 | `admin.users.delete` | `DELETE /api/users/admin/{user_id}` |
| 用户管理 | 绑定角色（打开弹框） | `admin.users.bind_roles` | `GET /api/admin/rbac/users/{user_id}/roles`（回显） |
| 用户管理 | 保存角色绑定 | `admin.users.bind_roles.save` | `POST /api/admin/rbac/users/{user_id}/bind-roles` |
| 权限管理-角色Tab | 新增角色 | `admin.roles.create` | `POST /api/admin/rbac/roles` |
| 权限管理-角色Tab | 编辑角色 | `admin.roles.update` | `PATCH /api/admin/rbac/roles/{role_id}` |
| 权限管理-角色Tab | 绑定权限点（打开弹框） | `admin.roles.bind_permissions` | `GET /api/admin/rbac/roles/{role_id}/bindings`（回显） |
| 权限管理-角色Tab | 保存权限点绑定 | `admin.roles.bind_permissions.save` | `POST /api/admin/rbac/roles/{role_id}/bind` |
| 权限管理-角色Tab | 菜单绑定（打开弹框） | `admin.roles.bind_menus` | `GET /api/admin/rbac/roles/{role_id}/bindings`（回显） |
| 权限管理-角色Tab | 保存菜单绑定 | `admin.roles.bind_menus.save` | `POST /api/admin/rbac/roles/{role_id}/bind` |
| 权限管理-菜单Tab | 新增菜单 | `admin.menus.create` | `POST /api/admin/rbac/menus` |
| 权限管理-菜单Tab | 编辑菜单 | `admin.menus.update` | `PATCH /api/admin/rbac/menus/{menu_id}` |
| 权限管理-菜单Tab | 隐藏/显示菜单 | `admin.menus.visibility.update` | `PATCH /api/admin/rbac/menus/{menu_id}` |
| 文章管理 | 新增文章 | `admin.posts.create` | `POST /api/posts` |
| 文章管理 | 编辑文章 | `admin.posts.update` | `PATCH /api/posts/{post_id}` |
| 文章管理 | 删除文章 | `admin.posts.delete` | `DELETE /api/posts/{post_id}` |
| 文章管理 | 置顶/取消置顶 | `admin.posts.pin.update` | `PATCH /api/posts/{post_id}`（`is_pinned`） |
| 文章管理 | 精选/取消精选 | `admin.posts.feature.update` | `PATCH /api/posts/{post_id}`（`is_featured`） |
| 文章管理 | 立即发布 | `admin.posts.publish.now` | `POST /api/admin/ops/posts/{post_id}/transition?to_status=approved` |
| 文章管理 | 立即下线 | `admin.posts.offline.now` | `POST /api/admin/ops/posts/{post_id}/transition?to_status=offline` |
| 文章管理 | 保存定时发布/下线 | `admin.posts.schedule.update` | `PATCH /api/posts/{post_id}`（`published_at`/`offline_at`） |
| 运营看板 | 查看看板 | `admin.dashboard.view` | `GET /api/admin/ops/dashboard`、`GET /api/admin/ops/trends` |
| 运营看板 | 导出 CSV | `admin.dashboard.export.csv` | `GET /api/admin/ops/export?format=csv` |
| 运营看板 | 导出 XLSX | `admin.dashboard.export.xlsx` | `GET /api/admin/ops/export?format=xlsx` |

映射约束：
- 同一个按钮允许映射多个只读接口（如“查看看板”），但写接口应唯一归属。
- 若一个 API 被多个按钮复用，必须在权限网关层按业务动作二次区分（避免越权）。
- 所有写接口需在审计日志中记录：操作者、动作、目标、结果。

#### ADM-UI-01 权限中心信息架构
- 权限管理采用 Tab：
  - 角色管理
  - 菜单管理

#### ADM-UI-02 绑定交互
- 用户列表通过弹框执行“给用户绑定角色”。
- 角色列表通过独立弹框执行：
  - 给角色绑定权限点
  - 给角色绑定菜单

#### ADM-UI-03 列表操作列交互规范
- 后台管理列表“操作”统一采用文字操作项（如：`编辑 | 删除`），不使用按钮形态。
- 操作项点击行为保持原业务逻辑不变，支持权限控制下的显隐。
- 文章管理页“操作列”不固定在右侧，需跟随表格横向滚动。

#### ADM-UI-04 左侧导航与信息密度
- 左侧导航采用紧凑布局，支持较窄宽度显示。
- 左侧导航需展示二级说明文案（如“撰写与列表”）。
- 导航文本在窄宽下采用省略策略，不得导致主内容区被压缩错位。

#### ADM-UI-05 搜索筛选与分页布局规范
- 搜索输入框在后台管理页中独占一行显示。
- 其他筛选控件采用固定宽度显示，并与右侧边界保持留白。
- 分页区域需与列表滚动区域分层：
  - 分页容器独立占满可用宽度；
  - 列表容器保留滚动能力（横向/纵向按需）。
- 分页信息与分页按钮默认同一行展示；窄屏时允许自动换行但不得被裁切。

#### ADM-UI-06 右侧内容区自适应规则
- `admin-content` 容器需保证内容可见，不允许因裁切导致右侧内容不可见。
- 在常见分辨率（如 1366x768）下，后台页面需自动收缩间距并保持结构稳定。
- 搜索条件、分页、列表在不同分辨率下均需满足：
  - 不溢出右边框；
  - 不遮挡关键操作；
  - 不出现整体布局错乱。

#### ADM-AUD-01 权限审计
- 记录权限相关变更（操作者、对象、动作、前后状态）。

### 5.4 内容运营与工作流（OPS）

#### OPS-WF-01 工作流
- 文章状态机：草稿、待审、已发布、已下线、驳回。
- 支持立即发布/下线、批量操作。

#### OPS-WF-02 定时执行器
- 基于 `published_at` / `offline_at` 自动执行。
- 应用启动补偿 + 周期扫描执行。

#### OPS-POST-01 文章运营台
- 多维筛选：关键字、状态、分类、标签、置顶、精选。
- 多维排序：创建时间、热度、权重、浏览量、发布时间。
- 快捷操作：置顶、精选、立即发布、立即下线。

#### OPS-DASH-01 运营看板
- 总览指标、趋势分析、Top 内容。
- 支持时间范围筛选。
- 支持导出 CSV/XLSX。

#### OPS-SEARCH-01 搜索运营
- 热搜词管理、屏蔽词、同义词配置。

#### OPS-CMT-01 评论治理
- 敏感词、黑名单、自动折叠与人工复核。

### 5.5 技术与风控（TECH）

#### TECH-RSK-01 反刷策略
- 行为频控、去重窗口、异常行为识别。

#### TECH-DATA-01 幂等与并发
- 互动接口幂等。
- 高并发计数不丢失不双加。

#### TECH-AUD-01 全链路审计与回滚
- 配置、权限、流程、运营动作全链路可追踪。
- 关键配置支持版本化与回滚。

#### TECH-GRY-01 灰度开关
- 功能级开关与比例配置（0~100%）。
- 支持策略灰度与指标护栏。

## 6. 非功能需求

### 6.1 安全
- 认证鉴权完整（Token、权限、数据范围）。
- 敏感操作二次确认。
- 关键入口限流（登录、评论、上传、互动）。

### 6.2 性能
- 列表与看板接口支持分页/过滤/索引优化。
- 高并发场景保证操作响应与计数一致性。

### 6.3 可用性
- 健康检查可用，异常可诊断。
- 关键任务（定时发布/下线）具备补偿机制。

### 6.4 可维护性
- 模块化分层（模型、服务、路由、前端页面）。
- 需求 ID 与接口、测试用例保持可追踪映射。

## 7. 数据与接口原则

### 7.1 数据原则
- 主键唯一、关键业务键唯一（如 slug、角色 code）。
- 重要行为可追踪，关键字段有明确业务口径。

### 7.2 接口原则
- 写接口默认幂等设计。
- 统一错误语义（鉴权、参数、业务、系统）。
- 统一分页结构（items + total）。

## 8. 验收标准

### 8.1 功能验收
- 每个需求 ID 至少包含：前置条件、操作步骤、预期结果。
- 关键链路（权限、工作流、看板、导出）必须可回归。

### 8.2 质量验收
- 幂等、并发、越权、风控、调度补偿均通过测试。
- 线上部署后健康检查与核心接口可用。

### 8.3 业务验收
- 运营可独立完成：配置角色菜单、发布文章、设置运营位、查看趋势、导出数据。
